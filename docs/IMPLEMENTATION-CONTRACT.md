# Stage 01 implementation contract

Local-first implementation of V3, FastAPI+SQLAlchemy+PostgreSQL and Next.js/TypeScript. Root owns infrastructure/docs/verification. Backend worker owns backend/. Frontend worker owns frontend/. QA worker owns tests/ and independently reports bugs. No changes to source templates, no generation, no real project approval by agents.

## Backend shape

`backend/app/main.py` exports `create_app(database_url=None, storage_dir=None)` and `app`. SQLAlchemy models in app/models.py; app/db.py exposes Base, make_engine or equivalent documented test API. Env DATABASE_URL, STORAGE_DIR. Alembic migration required. Bootstrap CLI creates owner tenant+admin from stdin password, no built-in default password.

API `/api/v1` JSON errors `{"error":{"code":"...","message":"...","details":...}}`.
Auth cookie session; login body username/password; response {user:{id,username,display_name,role,tenant_id},csrf_token}. `GET /auth/me` same; `POST /auth/logout`. Mutating authenticated calls require X-CSRF-Token. roles ADMIN/PM/ACCOUNT/VIEWER; ADMIN provisions same-tenant users POST /users {username,password,display_name,role}. PM/ADMIN confirms+approves, ACCOUNT edits, VIEWER read-only. Server actor and tenant always from session. Reject cross-tenant resources404.

`GET /questions` -> {template_version,questions:[{code,label,group,required,help_text,value_type,options?}]}; all core16 and source conditional groups. Group applicability from structured CORE06 categories, CORE09 language, CORE16 production mode; do not delete hidden answers.

`GET /projects` -> {items:[{id,name,customer,revision,status,updated_at}]}; `POST /projects` {name,customer} -> detail. `GET /projects/{id}` -> {id,name,customer,revision,status,template_version,answers:[{question_code,scope_id,value,raw_text,status,revision,source_id,evidence_locator,confirmed_by,confirmed_at}],sources:[],feedback:[],approvals:[],snapshots:[],validation:{can_submit,blockers:[],clarifications:[],applicable_codes:[],completion},stage02:{allowed,reason}}. Validation entries code/question_code/message/severity; unknown fields not silently confirmed.

`PUT /projects/{id}/answers/{code}` {expected_revision:<project revision>,value:<json>,raw_text?,status:ANSWERED_UNCONFIRMED|UNKNOWN|NEEDS_CONSULTATION|NOT_APPLICABLE|CONFLICTED,scope_id?:string,source_id?,evidence_locator?} returns detail; optimistic lock project revision. Never let client set CONFIRMED or confirmed_by. Non-core branch answers may be free text; delivery-specific via scope_id. `POST /projects/{id}/confirm` {expected_revision,question_codes:[...],scope_id?:string} PM/admin only -> detail. Confirmation for existing values only, no unconditional batch confirm unknowns.

CORE structured fields: CORE06 value {items:[{id,category,quantity,duration_seconds,aspect_ratio,language,variants:[{id,label,counts_as_separate:boolean}]}],variant_policy:"..."}; CORE09 {on_screen:["vi"],voiceover:[...],subtitles:[...]}; CORE13 {preview_due:ISO8601,final_due:ISO8601,publish_date:ISO8601|null,timezone:"Asia/Bangkok"}; CORE14 {approver_name,approval_role,contact}; CORE15 {budget_status:"CONFIRMED"|"CONSULTATION",amount:number|null,currency,revision_rounds:number}; CORE16 {production_mode:"HYBRID"|"GENERATIVE_AI"|"NO_AI"|"FOOTAGE"|"AE",rights_status:"CLEARED"|"PLANNED"|"UNKNOWN",rights_notes,ai_consent:boolean|null}. Core other values strings. Required core fields must validated semantic not just nonempty. CORE05 may explicitly NONE for nonadvertising; CORE12 NONE allowed; CORE11 planned resources with owner allowed before generation, unknown rights status not cleared.

Source APIs `POST /projects/{id}/sources` multipart file+expected_revision; allowed text/md/docx/pdf (10MB max), UUID storage/no client paths; raw originals retained. PDF scan unextractable recorded with manual fallback. `GET /projects/{id}/sources/{source_id}/download`; `POST /projects/{id}/prefill` {expected_revision,source_id} deterministic suggestion adapter parses explicit CORE-XX: text markers only; always PROPOSED_FROM_SOURCE, does not invoke LLM; conflict with existing different value CONFLICTED, never overwrite confirmed silently. Raw extraction is visible. Non-marker sources still useful evidence/manual mapping. Reject archive/executable/invalid MIME/content. DOCX zip bomb protections.

`POST /projects/{id}/validate` returns detail; `POST /projects/{id}/feedback` {expected_revision,message} returns detail. `POST /projects/{id}/submit` {expected_revision} -> detail includes latest candidate snapshot {id,hash,stage_version,created_at,status}. Only no blockers and confirmed applicable required values. `POST /projects/{id}/decision` {expected_revision,snapshot_id,content_hash,decision:"APPROVED"|"CHANGES_REQUESTED"|"REJECTED",notes} -> detail; PM/admin; reject stale version/hash, write immutable event, approval atomically. Feedback alone doesn't approve. Any answer/source mutation after approval increments revision, marks stage01 STALE and stage02 blocked, preserves old snapshot/event. GET `/projects/{id}/stage02` {allowed,reason,snapshot_id?} gates actual handoff, no stage02 production implemented.

`GET /projects/{id}/package?format=zip|json|docx|pdf&snapshot_id?` creates actual downloads from current draft or immutable snapshot (auth+tenant), default draft visibly labeled. ZIP includes folder information, review/checklist, answer/evidence, normalized brief, delivery matrix, rights index, acceptance criteria, gaps, manifest hashes and decision; six subfolders. Bound file hash, no fake checksum or approval. `GET /projects/{id}/audit` {items:[]} append-only events/revisions. Read package exports audit optional does not change source revision.

UI: Vietnamese sidebar 8 stages (only01 available), dashboard, create project, questionnaire wizard grouped core steps+adaptive branches, structured inputs above, source upload/preview/prefill manual suggestion label, save explicit/autosave debounce concurrency-safe, per-answer and batch confirmation, blockers+clarification panel, review/feedback/submit, candidate hash+decision, immutable snapshot list and package downloads. Account role cannot see working approve control; backend still enforces. Never label app as fully implemented stages02–08.
